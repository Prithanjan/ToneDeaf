# Scorer runtime dependencies — EXACT pins.
#
# Pinned exactly, not with ranges, because a range makes the parity set unverifiable: two tiers built a
# day apart would carry different transitive versions while claiming the same release
# (architecture.md §5.1, rules.md R-06). Versions match the blueprint's tech stack table and the
# Gateway's pins for every package the two services share.
#
# Python 3.12 (decision D-10). NOT 3.14 — no onnxruntime or numpy 2.1.3 cp314 wheels exist, and this
# workstation has 3.14.5 installed. The container pins python:3.12-slim; locally use
# `uv python install 3.12`.
#
# ONNX RUNTIME IS DELIBERATELY ABSENT FROM THIS FILE.
# It is the ONE dependency that differs between the two Scorer images, and it is selected by the
# ORT_PACKAGE build argument in scorer/Dockerfile:
#
#     onnxruntime-gpu==1.20.1   →  sih26104/scorer-gpu   (aws-gpu tier, CUDAExecutionProvider)
#     onnxruntime==1.20.1       →  sih26104/scorer-cpu   (local-cpu tier, CPUExecutionProvider)
#
# Listing one of them here and overriding it in the other image would mean this file describes only one
# of the two images while appearing to describe both. Naming neither, and pinning the version in
# exactly one place (the Dockerfile's ORT_VERSION arg), keeps the divergence visible at the point where
# it is decided. scorer/tests/test_packaging.py asserts both variants resolve to the same version, so
# a bump to one wheel that misses the other fails a test rather than shipping a version-skewed pair.
#
# grpcio-tools is NOT a runtime dependency. Stub generation happens in CI via scripts/gen_proto.sh and
# the generated modules are committed; a code generator in a serving image is unused attack surface.
