### Mandatory Corrections Before Incorporation

The final package adopts the fallback specification’s intent but corrects four assertions that would otherwise be misleading. CPU and GPU images cannot be **byte-identical** when one contains `onnxruntime` and the other `onnxruntime-gpu`; the invariant must instead be the application source, protobuf contract, model/calibration artifact hashes, migrations, policy bundle, and test suite. A CPU p95 target cannot be guaranteed before it is measured on the exact model and demo machine. A no-password JWKS issuer is a restricted test harness, not authentication, and must not be presented as real RBAC. Finally, `cloudflared` or `ngrok` is optional external public reachability, not an offline or zero-dependency fallback property.

| Caddy reverse proxy documentation: https://caddyserver.com/docs/caddyfile/directives/reverse_proxy | Caddy supports WebSocket upgrades by transitioning an HTTP upgrade into a bidirectional tunnel. It closes open WebSocket connections during configuration reloads. | Caddy is acceptable as the local TLS/WSS edge, but the rehearsal must include reconnect/backoff behavior and configuration cannot be reloaded during a live judge stream. Keep the Gateway unexposed on the host and proxy it only through Caddy. |

The supplied PS104 statement and outcome/privacy report remain the governing product requirements. Public benchmarks inform the model and evaluation approach; they do not replace consent, privacy constraints, or Indian-language deployment testing.
